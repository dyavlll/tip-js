## 1. Что здесь вообще разработано

Предметная область — список задач. Одна задача хранит id, title, completed и priority. В серверной версии появляется categoryId — ссылка на категорию. id — идентификатор записи, а не номер её позиции в массиве. Например, у второго элемента id = 4, хотя индекс равен 1.

ПР1 — консольная функция расчёта прогресса. ПР2 — операции с массивом объектов. ПР3 — страница HTML, кнопки и события. ПР4 — форма и сохранение в браузере. ПР5 — клиент для готового HTTP API. ПР6 — браузерное приложение, которое изменяет данные через API. Контрольные проверяют конкретные общие сценарии этих этапов.

HTML задаёт структуру страницы, CSS — её оформление, JavaScript — поведение. DOM — объектное представление HTML в памяти браузера. Node.js позволяет выполнять JavaScript вне браузера, например запускать сервер и консольные проверки. npm запускает команды, описанные в package.json; это отдельный инструмент экосистемы, а не сам язык.

В КР1 источником истины служит currentTasks в памяти страницы. В ПР4 состояние дополнительно записывается в localStorage. В ПР6 источником истины служит сервер: клиент отправляет изменение, после успеха заново получает список.

## 2. JavaScript после C++ и Python

### Переменные и типы

В C++ тип переменной объявляется и проверяется до выполнения. В JavaScript тип принадлежит значению: одна переменная let может получать значения разных типов. Python тоже динамически типизирован, но правила преобразования значений отличаются.

let используется, когда переменной нужно присвоить другое значение. const запрещает повторное присваивание переменной. При этом const не делает объект неизменяемым: const tasks = []; tasks.push(task) допустимо. В решении исходные данные сохраняются за счёт создания копий, а не благодаря слову const. var в новом коде здесь не используется: у него другая область видимости и особенности поднятия объявлений.

Основные типы: number, string, boolean, undefined, null, bigint, symbol и object. Массивы и функции тоже являются объектами. number обычно представляет число с плавающей точкой; безопасные целые ограничены диапазоном от −(2^53 − 1) до 2^53 − 1. Поэтому для id используется Number.isSafeInteger(id), а не только проверка отсутствия дробной части.

undefined означает отсутствие заданного значения: например, find ничего не нашёл. null — явно заданное отсутствие: например, editingId = null означает режим создания новой задачи. Особенность языка: typeof null возвращает "object"; для проверки null нужно сравнение с null.

### Сравнение и преобразования

Используем === и !==: они не преобразуют типы перед сравнением. 4 === "4" даёт false; при сравнении через == язык мог бы преобразовать строку. completed === false требует именно логическое false. Выражение !completed принимает гораздо больше значений: 0, "", null и undefined тоже считаются ложными.

Ложные значения: false, 0, -0, 0n, "", null, undefined и NaN. Пустой массив [] и пустой объект {} считаются истинными. Поэтому проверка if (tasks) не доказывает, что в массиве есть задачи: требуется tasks.length > 0.

Number("20") даёт 20. Number("") даёт 0 — это причина сначала проверять пользовательский ввод. В progress строки запрещены и не преобразуются вообще. В форме строки ожидаемы, потому что input.value возвращает строку; там преобразование id выполняется осознанно. Number.isInteger("12") возвращает false, а Number.isInteger(12) — true.

### Синтаксис, который нужно узнавать

Объект { id: 4, completed: false } похож по назначению на запись или структуру, но его свойства могут создаваться динамически. tasks — массив таких объектов. task.id читает свойство; task["id"] делает то же самое. Индексация массива начинается с нуля.

Стрелочная функция task => task.id — краткая запись функции с одним аргументом и возвращаемым выражением. В task => { return task.id; } фигурные скобки создают тело и требуют return. Чтобы кратко вернуть объект, нужны скобки: task => ({ ...task, completed: true }). Без них фигурные скобки будут восприниматься как тело функции.

const { id, title } = value — деструктуризация: создание двух переменных из свойств объекта. Запись { id, title } — сокращение для { id: id, title: title }. Параметр priority = "medium" получает значение по умолчанию, если аргумент отсутствует или равен undefined.

Обратные кавычки создают шаблонную строку: `Задача ${id}` вставляет значение id в текст. Оператор условие ? a : b выбирает одно из двух выражений. && и || вычисляются с коротким замыканием и возвращают значения операндов. Оператор ?? подставляет запасное значение только при null или undefined, сохраняя 0, false и пустую строку.

task?.title безопасно читает свойство, если task не null и не undefined. Это не проверка правильности данных: существующее поле всё равно может иметь неверный тип.

### Функции и модули

Функция получает параметры и возвращает результат через return. Чистая функция зависит только от аргументов и не меняет внешнее состояние: getPendingTasks не обращается к DOM, сети или хранилищу. Поэтому её легко проверить отдельно от браузера.

export делает функцию доступной другому модулю. import { getPendingTasks } from "./task-service.js" импортирует именованный экспорт. В браузере точка входа подключается как script type="module"; в Node.js package.json содержит "type": "module". Сервер HTTP нужен для надёжной загрузки модулей; открывать HTML двойным щелчком через file:// не следует.

## 3. Массивы, ссылки и неизменность

filter возвращает новый массив элементов, для которых предикат дал true. Порядок сохраняется. map возвращает новый массив результатов преобразования. find возвращает первый подходящий элемент или undefined. some отвечает, существует ли подходящий элемент. every проверяет все элементы; для пустого массива результат true. Set хранит уникальные значения; сравнение размера Set id с длиной массива выявляет дубликаты.

filter и map сами по себе не гарантируют неизменность объектов: внутри callback можно случайно написать task.completed = true. В решении этого нет. Невыполненные задачи отбираются через filter(task => task.completed === false), а изменённая запись создаётся через { ...task, completed }.

Присваивание const other = tasks не копирует массив. Обе переменные будут ссылаться на один объект. [...tasks] создаёт новый массив, но вложенные задачи остаются теми же объектами. Это поверхностная копия. Для изменяемой задачи создаётся ещё и новый объект. Остальные объекты можно разделять, пока они не изменяются.

Порядок свойств при копировании существенен: { ...task, completed: true } сначала копирует исходные поля, затем заменяет completed. При обратном порядке исходный completed затёр бы новое значение.

В C++ копирование std::vector<Struct> обычно копирует сами структуры. В JavaScript массив объектов скорее напоминает контейнер ссылок на объекты. В Python тоже важно различать копию списка и копии вложенных словарей. Для нашего плоского объекта достаточно spread; вложенные изменяемые объекты потребовали бы отдельного решения.

## 4. Контракты и обработка ошибок

Контракт функции описывает допустимые аргументы и результат. Операции ПР2 возвращают { ok: true, tasks } либо { ok: false, error }. При отказе вызывающий код не заменяет currentTasks. Проверка result.ok выполняется до обращения к result.tasks.

Ошибки формы возвращаются по полям: errors.title, errors.id, errors.priority. Это позволяет показать сообщение рядом с нужным input. В HTTP-клиенте используется другой подход — исключение ApiError, которое отклоняет Promise и перехватывается через try/catch с await. Эти способы нельзя смешивать без понимания контракта.

Валидация отвечает, допустимы ли данные. Нормализация приводит допустимое представление к удобной форме: trim удаляет краевые пробелы, Number преобразует строковый id формы. trim не убирает пробелы внутри названия. Длина JavaScript-строки измеряется в кодовых единицах UTF-16: некоторые символы, например многие эмодзи, занимают две единицы. В этих заданиях используется обычная проверка .length.

### Задание 1. Прогресс

Файл practice-01/progress.js. Сначала проверяются оба аргумента: целые числа, totalTasks от 0 до 1000, completedTasks от 0 до totalTasks. Условие включает completedTasks > totalTasks, поэтому для (5, 6) выводится только ошибка. При (0, 0) возвращается «Задач пока нет» до деления; деление 0 / 0 дало бы NaN.

На защите можно сказать: «Я отделил проверку аргументов от вычисления. Для пустого набора есть ранний возврат. Округление применяется только при формировании вывода».

### Задание 3. Изменение completed

Функция setTaskCompleted(tasks, id, completed) сначала проверяет массив, положительный безопасный целый id, строго логический статус и наличие задачи. Только после проверок map создаёт результат. Для нужного id возвращается { ...task, completed }, для остальных — исходный объект.

При id = 4 и completed = true новое значение true, а в demoTasks остаётся false. Обновляется только completed; title, priority и id копируются. По времени это O(n): поиск и map оба линейны; их последовательное выполнение всё равно имеет линейный порядок сложности. Память нового массива — O(n), дополнительно создаётся один изменённый объект. Индекс 4 использовать нельзя: это был бы пятый элемент, которого в общем наборе нет.

## 7. КР2: HTTP, Promise и API

### Асинхронность с нуля

Сетевой ответ приходит не сразу. Promise представляет будущий результат: pending, fulfilled или rejected. async-функция всегда возвращает Promise. await внутри async-функции приостанавливает её продолжение до результата Promise, но не блокирует весь браузер. Пока сеть ждёт, интерфейс может обрабатывать другие события.

try { await api.getTaskById(999); } catch (error) { ... } ловит отклонение Promise. Если убрать await, try завершится раньше, чем запрос отклонится, и этот catch не поймает будущую ошибку. Альтернатива — api.getTaskById(999).catch(...).

В JavaScript обработчики и продолжения выполняются через цикл событий. Обычный синхронный код завершается первым, затем выполняются готовые микрозадачи Promise, затем последующие задачи, например таймеры. Не нужно говорить, что await создаёт отдельный поток для каждой функции.

Promise.all запускает ожидание нескольких независимых операций: здесь задачи и категории можно загружать параллельно. Результат получается после успеха всех; при отклонении одной операции общий Promise отклоняется. Это не означает автоматической отмены остальных запросов.

### Что передаётся по HTTP

Запрос содержит метод, адрес, заголовки и иногда тело. Ответ содержит статус, заголовки и иногда тело. GET читает данные, POST создаёт запись или выполняет предусмотренное API действие, PATCH частично изменяет запись, DELETE удаляет. Конкретные пути и форматы задаёт контракт учебного API.

200 — успешное чтение или изменение, 201 — создание, 204 — успех без тела, 400 — некорректный запрос, 404 — ресурс не найден, 409 — конфликт, 500 — серверная ошибка. Статус не равен логическому полю completed: это разные уровни.

Accept: application/json сообщает желаемый формат ответа. Content-Type: application/json описывает формат отправляемого тела. Тело PATCH { completed: true } сериализуется JSON.stringify. У GET в этом клиенте тела нет; фильтры находятся в адресе. Параметры кодируются URLSearchParams, поэтому пробелы и амперсанды не ломают URL.

### Задание 3. Фильтры на сервере

createApiClient создаёт транспортный клиент с baseUrl http://127.0.0.1:5505/api. createTaskApi добавляет предметные методы: getTasks, getTaskById и другие. Такое разделение позволяет отдельно проверять HTTP и схему задач.

getTasks({ completed: false, priority: "high" }) вызывает GET /api/tasks?completed=false&priority=high. Значение false нельзя отбрасывать проверкой if (value), иначе фильтр потеряется. Клиент пропускает только undefined, null и пустые строки. На исходном серверном наборе ответ содержит id [4, 13, 34] и meta.total = 3.

Это серверная фильтрация: условия уходят в query, а сервер возвращает выборку. Просто получить все задачи и применить локальный filter не выполнило бы условие задания. После получения клиент проверяет поля объектов, уникальность id и meta.total. Для этого API нет пагинации, поэтому total совпадает с длиной полученного массива.

### Задание 4. HTTP-ошибка

fetch обычно не отклоняет Promise из-за статуса 404 или 500: сервер прислал HTTP-ответ. Поэтому requestJson явно проверяет response.ok. Это поле истинно для статусов 200–299. При false клиент создаёт ApiError с kind = "http" и status = response.status, сохраняя код и сообщение сервера, если они доступны.

Для getTaskById(999) сервер отвечает 404. Вызов с await находится внутри try/catch, поэтому приложение выводит kind и status и продолжает работу. Наличие сетевого соединения не означает успешность операции.

Клиент различает http, network, invalid-response, timeout и aborted. network означает, например, отсутствие соединения; invalid-response — неожиданный формат успешного ответа. AbortController даёт сигнал отмены. Таймер ограничивает ожидание, а finally удаляет таймер и подписку, чтобы ресурсы не оставались после запроса. Ответ 204 возвращается как null без вызова response.json, поскольку тела нет.

### Задание 5. PATCH, затем GET

Файлы practice-06/src/app-controller.js и task-api.js. Контроллер находит задачу по id в текущем состоянии, инвертирует completed и вызывает api.setTaskCompleted. Метод отправляет PATCH /api/tasks/4 с JSON-телом { "completed": true }. После успешного ответа контроллер вызывает refresh, а тот снова getTasks с текущими фильтрами.

При фильтре completed=false задача 4 исчезает: теперь она выполнена и сервер не включает её в выборку. Удаления не было; при выборе всех или выполненных задач запись должна обнаружиться. На исходном наборе незавершённые id: [4, 7, 13, 19, 22, 28, 34]; после изменения: [7, 13, 19, 22, 28, 34].

Обновлять только текст кнопки недостаточно: состояние сервера, список и фильтры должны согласоваться. Повторный GET получает серверную истину. Во время мутации кнопки блокируются, ошибка показывается пользователю, а блокировка снимается в finally.

Перед новой загрузкой предыдущая отменяется. Номер generation защищает от устаревшего ответа: даже если старый запрос завершился позднее, он не должен перезаписать новый список. Отмена не означает откат уже принятого сервером изменения, поэтому после мутации выполняется загрузка.

Сервер курса хранит данные в оперативной памяти. Перезапуск или штатный reset восстанавливает учебный набор. Для этой работы PostgreSQL не используется. CORS разрешает браузерному клиенту обращаться к API с другого origin; CORS не заменяет авторизацию и не нужен для запросов Node.js таким же образом, как для браузера.

## 10. Частые вопросы и короткие ответы

**Чем JavaScript отличается от Java?** Это разные языки. Здесь JavaScript исполняется в браузере и Node.js.

**const делает массив неизменяемым?** Нет, он запрещает переприсваивание переменной. Неизменность обеспечивается способом работы с объектами.

**Почему ===?** Чтобы проверять значение без неявного преобразования типов.

**Почему completed проверяется через typeof?** Допустимы только true и false; строки "false" и число 0 контракту не соответствуют.

**Почему id не равен индексу?** id — стабильный ключ записи, а индекс зависит от порядка и фильтрации массива.

**Чем filter отличается от map?** filter выбирает исходные элементы по условию; map строит результаты преобразования каждого элемента.

**find вернёт массив?** Нет, один первый объект или undefined.

**Почему нельзя менять task.completed внутри map?** Тогда изменится объект исходного массива, поскольку он передан по ссылке.

**Копирует ли spread вложенные объекты глубоко?** Нет. Это поверхностное копирование.

**Что возвращает toFixed?** Строку для вывода. Сводка до форматирования хранит числовой процент.

**Почему отдельная ветка для (0, 0)?** Чтобы корректно описать отсутствие задач и не вычислять 0 / 0.

**Почему обработчик на ul?** Всплытие позволяет обработать кнопки всех карточек и сохранить подписку после замены дочерних элементов.

**event.target и currentTarget — одно?** Нет. target — исходный элемент события, currentTarget — элемент, на котором сейчас вызывается обработчик.

**Для чего closest?** Чтобы от span внутри кнопки подняться к кнопке, затем к карточке с id.

**Почему textContent?** Название должно отображаться текстом и не интерпретироваться как HTML.

**Что делает preventDefault?** Отменяет стандартное действие события, например навигацию при отправке формы. Это не остановка всплытия; для неё есть stopPropagation.

**Почему после обновления ПР3 данные теряются, а в ПР4 остаются?** В ПР3 они только в памяти страницы; в ПР4 записаны в localStorage и читаются при старте.

**Зачем version?** Для проверки совместимости структуры сохранения при её изменении.

**Почему JSON.parse в try/catch?** Повреждённая строка вызывает исключение. Дополнительно нужна проверка схемы успешно разобранного значения.

**JSON и объект JavaScript — одно?** Нет. JSON — текстовый формат обмена. Объект — значение в памяти; преобразования выполняют stringify и parse.

**Почему не localStorage.clear()?** Оно удалило бы все ключи этого origin, включая данные других частей приложения.

**Почему в progress строка запрещена, а в форме преобразуется?** У функций разные контракты: progress принимает готовые числа, форма — строковые значения полей.

**Что такое Promise?** Объект будущего результата асинхронной операции.

**await блокирует весь JavaScript?** Нет, он приостанавливает продолжение текущей async-функции.

**Поймает ли catch ошибку без await?** Синхронный try/catch вокруг возвращения Promise не перехватит его последующее отклонение.

**Почему fetch не бросил исключение на 404?** Получение HTTP-ответа успешно на транспортном уровне; статус нужно проверить явно.

**404 и отсутствие сети одинаковы?** Нет: при 404 сервер ответил, при сетевой ошибке пригодного HTTP-ответа может не быть.

**PATCH и PUT отличаются?** PATCH предназначен для частичного изменения; PUT обычно задаёт замену представления ресурса. Здесь API поддерживает PATCH.

**Зачем GET после PATCH?** Чтобы получить актуальную серверную выборку с текущими фильтрами.

**Задача 4 исчезла — значит удалена?** Нет, она стала completed=true и не соответствует completed=false.

**Зачем AbortController и generation одновременно?** Отмена экономит ресурсы, а проверка номера загрузки дополнительно защищает состояние от запоздалого ответа.

**Где база данных?** В этих работах сервер хранит учебные данные в памяти. localStorage относится к браузеру и отдельно от сервера.
